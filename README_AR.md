# متجر المبيعات الذكي — نسخة تجارية

هذه النسخة تحول نموذج `aiagent.py` التعليمي إلى تطبيق ويب قابل للتشغيل التجاري كأساس MVP:

- قاعدة بيانات SQLite دائمة لا تُحذف عند إعادة التشغيل.
- واجهة محادثة عربية للعملاء.
- بحث المنتجات والتحقق من المخزون.
- حساب التوصيل.
- إنشاء الطلب بعد تأكيد العميل.
- متابعة الطلب برقم الطلب والهاتف.
- لوحة إدارة محمية برمز سري.
- تحديث حالات الطلبات.
- API للصحة والمنتجات والطلبات.
- تشغيل اختياري مع Anthropic عبر متغير بيئة.

## التشغيل المحلي

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# عدّل ADMIN_TOKEN وأضف ANTHROPIC_API_KEY عند الحاجة
python app.py
```

افتح:

- واجهة العميل: `http://localhost:5000/`
- لوحة الإدارة: `http://localhost:5000/admin`
- فحص الصحة: `http://localhost:5000/health`

للتشغيل الإنتاجي:

```bash
gunicorn --workers 2 --bind 0.0.0.0:5000 app:app
```

## الحماية والبيانات

- لا تضع المفتاح السري داخل الكود أو Git.
- غيّر `ADMIN_TOKEN` قبل النشر.
- احتفظ بنسخة احتياطية من مجلد `data/`.
- استخدم HTTPS وReverse Proxy مثل Nginx في الإنتاج.
- غيّر `SEED_DEMO_DATA=false` بعد إعداد المنتجات الحقيقية.
- لا تستخدم SQLite إذا أصبح حجم الطلبات كبيرًا جدًا؛ انقل طبقة البيانات إلى PostgreSQL.

## ما الذي يجب تخصيصه لكل متجر؟

عدّل متغيرات `.env`:

- `STORE_NAME`
- `DB_PATH`
- `ANTHROPIC_API_KEY`
- `ANTHROPIC_MODEL`

ثم أدخل المنتجات الحقيقية بدل البيانات التجريبية. قواعد التوصيل موجودة في `db.py` داخل `create_order` ويمكن فصلها لاحقًا في إعدادات المتجر.

## حدود النسخة الحالية

هذه نسخة تجارية أولى قوية (MVP)، لكنها لا تدعي إتمام كل متطلبات شركة كبيرة. قبل البيع الواسع أضف:

- تسجيل دخول متعدد المستخدمين بدل رمز إداري واحد.
- PostgreSQL وRedis عند التوسع.
- نسخ احتياطي آلي.
- دفع إلكتروني بعد الحصول على اعتماد مزود الدفع.
- ربط WhatsApp أو الموقع الخارجي.
- سجل تدقيق ومراقبة ومحدد طلبات API.
- سياسة خصوصية وموافقة على معالجة بيانات العملاء.
